Project structure and app relationship

The repository contains two React Native client applications and the Angular Superadmin web console. The directory combines registration records from the two client apps; Superadmin is the control plane, not one of those two clients.

  • Energy Hub: energy_hub_app/, React Native; includes auth, registration, marketplace, and partner navigation flows.
  • Service Admin: service_admin_app/, React Native; includes API, screens, services, flows, and navigation.
  • Superadmin: superadmin/, Angular; guarded console routes, platform APIs, shared operations UI and account directory.
  • Backend: backend/ provides platform services and the Superadmin console API.

This UI change only touches the Angular Superadmin; the mobile apps and Backend were left unchanged.

Theme changes made

  • App Registrations app marks now use the existing Superadmin icon set: pulse for Energy Hub and tool for Service Admin. App-logo image elements were removed from its cards, filters and summary metrics.
  • Shared page headers now use the registrations page's blue-tinted surface, border, radius and shadow tokens.
  • Global light-mode surfaces now have clearer contrast: cool blue-gray page canvas, white cards, consistent blue-gray borders/shadows, and shared table-header/form-control treatments.
  • Profile and Notifications headings were aligned to that shared header treatment.
  • Settings heading decoration and oversized hard-coded button glow were removed; button colors now use theme variables, and its grid avoids narrow-screen overflow.
  • Profile avatar fallback styling was corrected to remain legible on the light surface.

Image handling: no images were added. Real profile photos and Gravity Hub brand marks remain because they are user/brand content, not decorative app icons. Registration icon assets were not deleted from disk because other clients or code may consume them.

Current data and storage audit

The configured database is PostgreSQL energy_hub. Superadmin accounts, role permissions, and audit history are stored in superadmin.console_state as a validated JSONB state document; the legacy JSON file remains only as a rollback backup. Operational page reads are authenticated and checked against the corresponding Superadmin page permission.

  • Admin pages are protected by authentication and page-level permission guards; Notifications is Superadmin-only.
